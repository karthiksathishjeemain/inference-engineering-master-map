SYSTEM TOUR

Inference is a resource-conversion system

10–15 min

Mental model: an inference server turns request bytes into tensor operations, moves those tensors through a memory hierarchy, and spends finite compute and bandwidth to emit tokens before a deadline.

The inference engineer’s first question is not “Which optimization is popular?” It is “Which finite resource is limiting this workload now?” Select each stage below and identify its resource, metric, and failure mode.

COMPUTE

From matrix multiplication to FLOPs

20–25 min

Why it exists: Transformer layers are dominated by matrix multiplications. Counting their operations gives a first estimate of work; counting their bytes reveals whether hardware can stay fed.

Intuition: each output element is a dot product. Multiplying an M×K matrix by a K×N matrix produces M×N outputs, each requiring K multiplies and K−1 additions. Counting a multiply-add as two operations gives approximately 2MKN FLOPs.

Work—2 × M × K × N

Arithmetic intensity—FLOPs per byte

Ideal traffic at one memory boundary: each input is read once and output written once. Accumulators may use wider precision; tiling, caches, rereads, and quantization metadata change traffic. Integer operations are not floating-point FLOPs.

# One linear projection: [tokens, hidden] @ [hidden, out]
y = x @ weight
# Approximate work
flops = 2 * tokens * hidden * out
UnderneathThe runtime chooses a GEMM kernel, tiles operands, and maps tiles to thread blocks and Tensor Cores.
Performance implicationLarger M reuses weights across more tokens, increasing arithmetic intensity.
Common mistakeHigh theoretical FLOPs do not help when the kernel waits for bytes or uses an unsupported shape.

MEMORY & PRECISION

Build a model-fit ledger

20–25 min

Why it exists: a model “fits” only after weights, KV cache, activations, temporary buffers, graphs, allocator fragmentation, and runtime reservations all fit at the same time.

First-principles rule: weight bytes = parameters × bytes per parameter. BF16 stores each weight in 2 bytes, so a 7B model needs about 14 GB (13.0 GiB) before overhead. Quantized storage also needs scales, sometimes zero-points, and possibly unquantized tensors.

Weight memory—parameters × bytes
Ideal GPU-count lower bound—equal weight shards + per-GPU reserve
KV / workload room—after weights + reserve

This count assumes perfectly divisible weights and a reserve on every GPU. It is not a deployable TP configuration: head divisibility, replicated tensors, KV, activations, and communication buffers still need checking.

14 GB weights + 8 GB runtime = 22 GB used
PrecisionLower-bit formats reduce capacity and bandwidth pressure, but need supported kernels and acceptable quality.
FragmentationReserved memory can exceed live tensors; inspect allocated versus reserved memory before declaring a leak.
Production implicationUnused memory is not waste when it is the safety margin for long prompts, bursts, and temporary buffers.

PCIe, NUMA, and network boundaries

15–20 min

Mental model: every boundary is a toll road. HBM feeds the GPU, PCIe connects host and device, an intra-node fabric connects GPUs, and the network connects nodes. The slowest unavoidable transfer can dominate the whole request.

Rates are illustrative sustained, one-direction bandwidths. 100 Gb/s = 12.5 GB/s before protocol overhead. Aggregate or bidirectional figures are not point-to-point payload bandwidth.

NUMAA CPU core accessing memory attached to another socket pays extra latency and consumes inter-socket bandwidth. Pin workers and memory near their GPU/NIC.
CollectivesTensor parallelism exchanges activations repeatedly. Topology matters because collectives synchronize the slowest rank.
OverlapMoving bytes can be hidden only when independent compute exists and the runtime schedules both concurrently.
ROOFLINE LAB

Compute-bound or bandwidth-bound?

20–25 min

Why it exists: arithmetic intensity connects algorithmic work to hardware capability. It is FLOPs divided by bytes moved. Compare it with the hardware ridge point: peak compute throughput (FLOP/s) divided by memory bandwidth (B/s).

Arithmetic intensity—FLOP / byte
Ridge point—peak FLOP/s ÷ bandwidth
Predicted lower bound——

Ceiling = min(peak compute, intensity × bandwidth). Minimum time = max(work ÷ peak compute, bytes ÷ bandwidth). Use the compute peak for the actual precision and dense/sparse path, and count bytes at the same memory boundary. The dot is a model ceiling, not a measured result. Launch, cache, and communication limits are omitted.

Memory-bound responseReduce bytes, reuse weights across more tokens, quantize, fuse operations, or increase bandwidth.
Compute-bound responseUse faster kernels, supported low precision, better tiling, fusion, or more compute capacity.
Reality checkThe roofline is an upper bound. Launch overhead, synchronization, shape inefficiency, and queueing make real time worse.

Sources & assumptions

Primary references behind the lessons. Hardware ceilings and calculators support reasoning; verify deployments with measured workloads and quality evaluations.

  • NVIDIA: GPU execution and performance — SMs, memory hierarchy, arithmetic intensity, and peak throughput.
  • NVIDIA: matrix multiplication — FLOP counts, tiling, shapes, and Tensor Core efficiency.
  • PyTorch: CUDA semantics and inference mode — asynchronous timing, synchronization, and model.eval().
  • Hugging Face: cache strategies — dynamic, static, quantized, offloaded, and sliding-window caches.
  • vLLM: metric definitions — TTFT, request-level TPOT, streaming intervals, and measurement boundaries.
  • PagedAttention paper — paging, memory sharing, and serving throughput.
  • NVIDIA NCCL: collectives — all-reduce, reduce-scatter, and all-gather.
  • vLLM, TensorRT-LLM, and TGI — check current support for your model and hardware.

Scope limits. Work models assume dense decoder Transformers and ordinary autoregressive generation. MoE uses active rather than total parameters for most compute estimates; MLA, sliding attention, multimodal inputs, speculative decoding, and distributed caches need additional terms.
